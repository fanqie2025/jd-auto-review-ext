## 它做什么

| 能力 | 说明 |
|---|---|
| **≥60 字硬保证（免 AI）** | 抓同款商品已发布的评价 → **随机抽 N 条（默认 10）好评当素材 → 按句拼成一条新评价**（默认组稿模式，不是整条照抄）→ 拼不出来才退回单条 → 再不行用内置模板兜底 |
| **尽量不重复** | 三重去重：① 用过的**句子**记进跨页面记忆，不再出现 ② 用过的**素材评价**优先排除 ③ 与最近 10 条发过的正文做句子重合度比对，**≥50% 就重抽素材重拼**（最多 3 次） |
| **一次只跑一个标签页** | 「运行权（lease）」机制：同一时刻只有一个标签页是驱动页，其他页只显示面板、**绝不操作**。点「去评价」如果开在新标签页，老页会**交权并停手**——不会再出现两个发布页同时上传、同时提交 |
| **文案来源可选** | 设置页下拉：`现成评价`（默认 · 免密钥）/ `现成优先，不够再用 AI` / `只用 AI` |
| **必须有图（免 AI）** | 取**该评价自带的买家秀图**（文图来自同一条评价，最自然）→ 用 canvas 重编码成真 JPEG（360buyimg 常返回 webp，京东按 magic bytes 校验会拒收）→ `DataTransfer` 注入 `input[type=file]` → 触发 `change` 上传 |
| **没法评价的单会自动跳过** | **京东外卖 / 服务类订单 / 卡片点不进去 / 落在不认识的页面 / 页面明说「暂无可评价 · 已评价过 · 评价已关闭」** → 一律排队跳过：不发表、**不计入上限**、回列表继续下一单，且跳过的商品本轮不会再点它。这类跳过**不触发**「连续跳过 3 单停手」（那是"没配到图"专用的） |
| **一张图都没配到** | 默认**跳过这一单**：不发表、**不计入上限**、回列表继续下一单；也可改成「暂停等我处理」或「无图也照发」。连续 3 单都没配到图会自动停下（多半是图片池空了 / 上传入口变了） |
| **自动打五星** | 老评价页点 `.star5`；新发布页四个维度默认就是「非常好」，不动它 |
| **自动闭环** | 发表 → 返回列表 → 下一单 → …直到列表清空 |
| **两条链路** | 老：`club.jd.com/myJdcomments/*`；新：`comment.m.jd.com/pc-static/{center,publish}` |
| **默认模拟** | 只填正文 / 打星 / 配图，**不点发表**，人工核对后再切到「真实」 |
| **防风控节奏（宁慢勿快）** | 所有等待走**随机区间**（绝不固定秒数）+ 两单之间长休息 + **单轮限单**到量自停 + 页面出现「正在维修/系统繁忙/安全验证」立刻停手 |
| **全程日志（排障用）** | 面板里实时滚动的日志区 + **跨页面续接**（评价流程要跳好几页，日志跟着走）+ 一键**复制 / 下载 / 清空** |

## 安装（Chrome / Edge 都一样，约 30 秒）

> 📥 **第 0 步 · 下载**：打开 **[下载页 / Releases](https://github.com/fanqie2025/jd-auto-review-ext/releases/latest)**，
> 下 `jd-auto-review-ext-v0.1.0.zip`（点开 Assets 里的那个文件）。
> 同目录还有一个**内容完全相同**的 `jd-auto-review-ext-v0.1.0.jar` —— 习惯用 `.jar` 后缀就下它，两者字节一致。
> 下完**解压**，得到一个 `jd-auto-review-ext` 文件夹。
>
> 直链（不想进页面的话）：[zip](https://github.com/fanqie2025/jd-auto-review-ext/releases/latest/download/jd-auto-review-ext-v0.1.0.zip) ·
> [jar](https://github.com/fanqie2025/jd-auto-review-ext/releases/latest/download/jd-auto-review-ext-v0.1.0.jar)

1. 打开 `chrome://extensions`（Edge 是 `edge://extensions`）
2. 打开右上角「**开发者模式**」
3. 点「**加载已解压的扩展程序**」，选择第 0 步解压出来的那个 `jd-auto-review-ext` 文件夹
   （**选文件夹本身**，不是里面的某个文件；也别放在下载目录里随手删，扩展是从这个文件夹实时读取的）
4. 装好后会自动弹出**设置页**；没弹就点工具栏上的扩展图标
5. **文案来源保持默认的「只用现成评价」就不用填任何密钥**，直接能用；
   只有把文案来源改成 AI 时才需要填 API 密钥

> **接口地址默认就是 DeepSeek 官方**（`https://api.deepseek.com/v1/chat/completions`，模型 `deepseek-chat`），不用改。
> 只有换成自建网关（比如 `http://192.168.1.100:8000/v1`）时，才要额外点一下设置页的「**授权当前接口地址**」。

## 使用

面板（**默认浅色**、左下角、拖标题栏可移动、位置记住）上的控件：

| 控件 | 作用 |
|---|---|
| **模式：模拟 / 真实**（分段按钮） | **只有两种**。模拟=只填正文/星级/图片不提交；真实=会点发表（切换会弹确认框） |
| **上限 [ N ] 条评价** | 本次最多**发表几条评价**，`0 = 不限`，面板里直接填。按「条」不按「单」——一个订单可能含多件商品，一次发表就产出好几条 |
| **保存** | 把当前「模式 + 上限」写回设置页，成为以后的默认。上面那行会显示`与设置页一致`或`本次：… （改了未保存）` |
| **开始 / 暂停** | 按当前生效的模式跑 |
| 日志栏 | `收起 / 复制 / 下载 / 清空` |
| 标题栏 | 左边是版本号（如 `v0.1.0`）；右边有 **「设置」按钮**（点一下打开扩展设置页）；按住标题栏可**拖动面板**（避免挡住页面按钮——原来固定右上角会压住「去评价」） |

**面板配色**（设置页「节奏与防风控 → 面板配色」）：`跟页面底色走`（默认；白页面 = 浅色面板）/ `始终浅色` / `始终深色`。
两套色板是同一套设计规范（hairline 分隔 + 单一强调色 + 负字距标题），只是明暗相反。

### 面板和设置页是什么关系？（同一份配置，两种权限）

**不是两套配置** —— 两者读写的都是 `chrome.storage.local.config` 那一份。区别只在「谁能改」：

| 项 | 面板 | 设置页 |
|---|---|---|
| **模式（模拟/真实）、上限条数** | ✅ 可改（属于**本次运行**），点「保存」写回设置页成为默认 | ✅ 改的是默认值 |
| **节奏**（点击前等待 / 步骤停顿 / 两单休息 / 上传上限） | ❌ 只读回显（面板那行写明「节奏（设置页）：…」） | ✅ 只能在这里改 |
| 文案来源 / 图片 / 大模型 / 面板配色 / 其它 | ❌ 只读 | ✅ 只能在这里改 |

两个配套机制：

- **实时同步**：监听了 `chrome.storage.onChanged`，在设置页点「保存设置」后，**面板立刻跟着变**（不用刷新京东页面）。
- **旧配置自动迁移**：早期版本的节奏是毫秒字段（`clickDelayMin: 4000`），现在统一存秒，程序会自动 `4000 → 4 秒` 并删掉旧字段。
- **配置兜底**：缺值补默认；**「上限」填 0 秒会被判为配置错误并回默认**（否则会变成"完全不等待"，很危险）；
  `最小 > 最大` 自动交换；负数归 0。这些都在 `src/pacing.js` 里，有单测覆盖。

1. 设置页有「**去京东评价页**」一栏，点一下就打开（新标签页，不会把设置页顶掉）：
   - 打开「评价中心」（新版）：`https://comment.m.jd.com/pc-static/center`
   - 打开「待评价订单」（老版）：`https://club.jd.com/myJdcomments/myJdcomment.action?sort=0`
   - 打开「我的订单」：`https://order.jd.com/center/list.action`
2. 打开后页面左下角出现面板 → 模式选「**模拟**」→ 点「**开始**」，人工核对浏览器里的表单
3. 确认无误 → 模式切成「**真实**」（弹确认框）→ 再点「开始」，这才是真发表
4. 想连续跑就点「开始」（受设置页「单轮最多处理几单」限制，默认 5 单到量自停）
5. 想停就点「暂停」（当前步骤做完后停）

## 测试（装完先点一遍）

设置页有「测试（建议装完先点一遍）」一栏，两个按钮，走的是**和实跑完全相同的代码路径**（都在 background 里）：

| 按钮 | 位置 | 它验证什么 |
|---|---|---|
| **探测模型** | 「大模型」栏，模型名右边 | GET `/v1/models` 列出该网关支持的模型 → **在下面渲染成一排可点的小按钮，点一下直接设为模型名**（并立即保存）；同时校验当前填的名字在不在列表里（大小写不一致会指出正确写法，完全不在会警告拼错）。探测结果会记住，下次打开设置页仍在 |
| **测试大模型** | 「大模型」那一栏里（和接口/密钥放一起） | 真发一次请求：接口通不通、密钥对不对、模型名对不对、**返回够不够 60 字**。失败会打出原始错误 + 六类常见原因 |
| **测试取现成评价** | 「文案来源」那一栏里 | 免 AI 模式的命脉：能不能抓到该商品的图文评价（条数 / 带图数 / ≥60 字条数 / 前 3 条样例），**并给出一份「实际会填进页面的文案」组稿预览** |

模型列表地址由接口地址自动推导：`…/v1` → `…/v1/models`，`…/v1/chat/completions` → `…/v1/models`。
少数自建网关没实现 `/v1/models`，那时会明确提示「接口通了但列表为空，请手填模型名」，不会误导你。

两个测试都会先保存你当前填的配置，测的就是你刚填的那一份。

**大模型测试会自动帮你处理两件容易踩的事：**
1. **自动申请接口域名的访问权限**——自建网关（如 `http://192.168.1.100:8000`）不在内置白名单里，不授权会直接 `Failed to fetch`；点「测试大模型」时会同步发起授权申请（已授权则不弹窗）。**用默认的 DeepSeek 官方地址不需要这一步**（`api.deepseek.com` 已在白名单里）。
2. **自动补全接口地址**——只填到 `/v1`（甚至只填域名）都能用，会自动补成 `/v1/chat/completions`，结果里会显示「实际调用地址（已自动补全）」。

**密钥必须是纯 ASCII**：HTTP 请求头只允许 ISO-8859-1，密钥里混进中文/全角空格时 `fetch` 会抛
`String contains non ISO-8859-1 code point`（完全看不出是哪个字符）。现在会提前拦下来并指名道姓：
`密钥里有非 ASCII 字符：第 7 个是「中」(U+4E2D)`。

> 「测试取现成评价」如果返回 **444 / 系统繁忙 / Forbidden**，说明该接口不接受后台发起的请求，
> 需要改成「借一个 `club.jd.com` 标签页来取数」——把测试结果发我即可。

## 弹窗拦截（Chrome 会挡住"点击后新开标签页"）

**原因**：扩展发出的点击**不是用户手势**，页面里任何 `window.open`（包括点击后异步调的）都会被 Chrome 弹窗拦截器挡掉
—— 地址栏右侧出现「已拦截弹窗」图标，表现就是"**点了没反应**"。

**扩展的处理**：页面一加载就把 `window.open` 换成"原地跳转"，并且返回一个**假窗口对象**：

- 页面照样拿到句柄（不会因为拿到 `null` 报错），`w.location = url` / `w.location.href = url` 都支持；
- 最终都变成**当前页跳转**，不再需要弹窗，也就不会被拦；
- 页面里合法的 `target="_blank"` 锚点也会被一起中和成同页跳转；
- 日志里会记一行「拦到 window.open，改成原地跳转 + URL」，方便核对；
- 设置页可关掉（「把页面的新开标签页改成原地跳转」），关掉后就得靠浏览器放行。

**万一还是被拦（关了这个开关，或页面用了别的方式开窗口）**：
点地址栏右侧的「已拦截弹窗」图标 → 选「**始终允许**」；或到 `chrome://settings/content/popups`
把 `https://comment.m.jd.com` 和 `https://club.jd.com` 加进允许列表。

## 一次只跑一个标签页（运行权）

**为什么需要**：点「去评价」如果被页面用新标签页打开，老标签页会以为"没跳转"继续点下一个候选 ——
结果是**好几个发布页同时在跑**：同时上传图片、几乎同时点提交。这是必须避免的。

**怎么做的**：

- 每个标签页开工前先申请一份**运行权**（`chrome.storage.local` 里的 `JDAR_LEASE` = 一组槽位 `{tabId: 心跳时间}`）；
- 拿到运行权的是**驱动页**，每 10 秒续约；**其他页只显示面板，不执行任何操作**（也绝不提交）；
- 同时允许几个驱动页由设置页「**后台并发**」决定，**默认 1**，可填 1~5（非法值自动回默认/封顶）；
- 驱动页 30 秒没续约（被关掉/崩了）→ 其他页可以**接管**；
- 点「去评价」后如果本页没跳转：**先交出运行权**（万一页面是开在新标签页，由那个标签页接手）；
  **8 秒后如果没有任何标签页接手**，就判定"这一单点不进去"（外卖单 / 服务单 / 已评价的单常这样）→
  **跳过它、回列表继续**，不会像以前那样整轮停在那儿等人；
- 列表步骤的点击**只尝试一次**（原来会依次点 4 个候选，正是"开出多个标签页"的根源）；
- 点「发表/发布」之前**再确认一次**自己仍是驱动页，不是就不提交。

> 让权只影响"谁来继续跑"，**不影响提交保护** —— 真正防"两单同时提交"的是发布页那道 `canDrive()` 检查。

单轮上限（按评价条数）与运行权是两道独立保险：一个防"发太多"，一个防"同时发"。
## 哪些单会被自动跳过（不计入上限）

**跳过 = 不发表、不计入上限、回列表继续下一单**，并且**跳过的单本轮不会再点它**
（在列表页按商品名指纹过滤；"点进去发现没法评价"的情况靠跨页面记住的「上一张卡片指纹」认出来）。

| 情况 | 怎么认出来的 |
|---|---|
| **京东外卖 / 服务类订单** | 卡片点进去没反应，或落在不认识的页面 → 判定"点不进去"，跳过 |
| **卡片点了没反应** | 点完等 2.5 秒 URL 没变 → 先交权 8 秒；没人接手就跳过这张卡片 |
| **页面明说不能评价** | 找不到输入框时，扫页面文案：`暂无可评价 / 没有可评价 / 无待评价 / 暂不支持评价 / 不支持评价 / 不可评价 / 无法评价 / 不能评价 / 已关闭评价 / 评价已关闭 / 该订单已评价 / 订单已评价 / 已评价过 / 评价活动已结束 / 评价已结束` |
| **落在不认识的页面** | 3 分钟内刚点过卡片、又不在我们支持的页面清单里 → 跳过那张卡片 |
| **一张图都没配到** | 该商品没有可复用的带图评价 |

两条不同的"连续计数"规则：

- **"没法评价"的跳过不计连续数** —— 这是订单本身的性质，不是出故障。每张卡片一轮只点一次，列表有限，自然收敛；
- **"没配到图"连续 3 单就停手**（`MAX_SKIP_STREAK`）—— 这多半意味着图片池空了 / 上传入口改了，停下来比继续空转好。

> 保守优先：**只有当页面上找不到评价输入框时**才会去扫"不能评价"的文案 ——
> 正常的发布页就算正文里出现这些字眼也不会被误判。既没输入框、页面又没说"不能评价"时，
> **宁可停下问你**，也不瞎猜着跳过。

## 日志（排障用）

- 面板下半部分就是**实时日志**，每一步都记：页面载入、评价池条数、文案来源与字数、图片张数、填字后页面计数是否认账、点击动作、发布后页面反馈片段、风控命中、异常。
- **跨页面续接**：评价流程会在 `club.jd.com` / `comment.m.jd.com` 之间跳好几页，日志统一写进 `chrome.storage.local`（最多留 800 条），新页面打开时会把之前页面的日志读回来显示，中间有 `===== 本页 … =====` 分隔。
- 三个操作：**复制**（进剪贴板）/ **下载**（存成 `jdar-log-<时间>.txt`，在浏览器下载目录）/ **清空**。
- 每行格式：`[时:分:秒] 级别 消息 {附加数据}`，附加数据超长会截断，不会把日志撑爆。
- 出问题请把下载下来的 txt 发我 —— 有了它就能直接定位卡在哪一步。

| **同一轮不重复用同一张图** | 开 | 降低图片查重 |
| 自动配图 | 开 | |
| 没法评价 / 没配到图时 | **跳过这一单** | `跳过`（不计入上限，继续下一单）/ `暂停`（等人工）/ `无图也照发`（只影响"没图"；"没法评价"的单仍然跳过，因为没有输入框） |

| 上限条数（按评价条数算） | **5**（0=不限） | 到量自动停，提示你隔几小时/隔夜再跑。**填 0 = 不限**。新评价中心是「一个订单一件商品、单独评价」，所以一条 = 一件商品；老评价页一页可能多件商品，检查发生在「点发表之前」，**整单会一起发完、不会半路截断**（代价是可能略微超过上限）。发表前还会再挡一道 |
| **后台并发** | **1（关闭）** | 同一时刻允许几个标签页同时跑。**默认关闭**：其他页只显示面板、不操作也不提交；**想开（填 2~5）会先弹一次确认**，确认后才生效，开启时设置页显示「已开启并发 · 风险」红标、面板也会标「已开并发 ⚠ 风险」。多条评价会几乎同时提交、风控特征明显，非必要别开 |
| 分块打字 | 开 | 页面字数计数不认账时，自动改成 6~14 字一块地"打字"重填 |
| 遇风控停手 | 开 | 页面出现「正在维修 / 系统繁忙 / 安全验证」等立刻停 |
| 图片上传方式 | **一张一张注入** | 每张之间随机停顿；也可改成「一次性全部注入」 |
| 每批几张 · 批间隔 | **1 张 / 1.5~4 秒** | 模拟人手一张张选文件（一次性塞 3 张 = 3 个请求齐发，最像脚本） |
| 等上传完成 | **8~15 秒（随机）** | 注入完随机等一段时间再点发表；旧评价页另有「上传上限」兜底 |

> **节奏的单位统一是「秒」**（界面上填秒，支持小数如 2.5）：程序内部自己换算成毫秒，
> 并在「最小~最大」之间随机取——固定秒数本身就是脚本特征，所以绝不出现固定值。
> 换算逻辑在 `src/pacing.js` 的 `sec2ms()`，有单测覆盖。

## 安全 / 风控（重要）

**核心原则：宁慢勿快。** 京东的限流是**行为触发**的——同样一次点击，固定 5 秒一次和随机 4~9 秒一次，后者安全得多。

已经内置的保护：

1. **所有等待都是随机区间**——不存在固定秒数（固定节奏本身就是脚本特征）；
2. **两单之间强制休息 25~60 秒**（最容易踩风控的地方）；
3. **点「发表」前额外多等 2 秒**（最敏感的一步）；
4. **单轮限单**：默认跑满 5 单就自动停，并提示你隔几小时/隔夜再来；
5. **遇风控立刻停手**：页面一出现「正在维修 / 系统繁忙 / 安全验证 / 操作过于频繁」就停止流程，
   并明确提示**不要反复重试**（重试只会延长封锁）；
6. **填字有校验**：读页面自己的「已写 N 字 / N / 500」，对不上就改成逐字输入——避免"以为填上了其实没填"
   然后稀里糊涂提交；
7. **默认模拟**：先只填不提交。

按默认节奏，**一单大约 30~45 秒，加上两单之间休息，5 单（默认上限）约 5~9 分钟**。

其它注意事项：

- 首次一律用**模拟**，核对后再切「真实」；正式跑放闲置时段、单次完成。
- 该扩展**不采集、不上传**任何账号信息；密钥只存在 `chrome.storage.local`（本机浏览器里）。
- 评价发布**不可撤销**，这是把「模拟」设为默认的原因。

## 发版（怎么重新打包）

改完代码后，**双击 `tools\pack.cmd`**（或 `pwsh -File tools\pack.ps1`）即可，它会：

1. 从 `manifest.json` 读版本号；
2. 把扩展目录下除 `.git` / `tools` / 上次产物之外的文件打进压缩包，顶层保持一层 `jd-auto-review-ext/`；
3. 输出 `jd-auto-review-ext-v<版本>.zip` 与**内容完全相同**的 `.jar`（`.jar` 本身就是 zip 格式，只是后缀不同）；
4. 打印文件数、字节数与 SHA256 —— 上传 Release 后可用它核对附件。

默认输出到扩展目录的上一级，也可 `-OutDir D:\某处` 指定。产物已在 `.gitignore` 里，不会误提交。

## 排障

| 现象 | 原因 / 处理 |
|---|---|
| 页面没有面板 | 页面不是受支持的地址；或扩展被停用（`chrome://extensions` 看有没有报错） |
| 提示「后台无响应（扩展可能被重新加载）」 | 你在扩展页点过「重新加载」，刷新一下京东页面即可 |
| 提示没填密钥 | **只有把「文案来源」改成 AI 才需要密钥**；保持默认的「只用现成评价」不用填 |
| 面板说「页面计数与我们填入的字数对不上」 | 已经自动改成逐字重填；若仍对不上，人工看一眼输入框再决定要不要继续 |
| 停在「本轮已处理 5 单（上限 5 单）」 | 单轮限单生效（防风控）。隔几小时或隔夜再点「开始」 |
| 面板说「出现风控/维护提示，已立刻停手」 | **别再点开始了**，这是被软封的签名，等几小时到一天自解 |
| **碰不到页面按钮** | 面板**默认在左下角**、拖标题栏可移动、位置会记住（原来固定右上角，正好压住新评价中心右侧那列「去评价」按钮） |
| **点了「去评价」没跳转** | 现在会按「最里层元素 → 往上 4 层祖先」依次尝试点击，每次点完等 2.5 秒**验证 URL 是否变化**；仍没反应 → 先交权 8 秒（万一是开在新标签页）→ 没有任何标签页接手就**判定"这点不进去"、跳过它继续**，日志里会写明它点了哪个标签/类名/文本 |
| **外卖单 / 服务单一直在跳** | 设计如此：跳过但不计入上限。如果列表全是这类单，跳完所有卡片后会提示「新评价中心没有待评价卡片了」 |
| **跳到不认识的页面就停手了** | 说明"上一张卡片指纹"已过期（超过 3 分钟）或拿不到。刷新回列表页再点「开始」即可；日志里会有一行「进入了不认识的页面」 |
| **明明有输入框却提示"没找到"** | 页面可能还没加载完 → 刷新重试；一直这样说明京东改版了，把日志发我（要改的是 `newPublishStep()` 里的 `textarea.rate-comment-content-textarea`） |
| **提示「扩展刚被重新加载过，本页面里的旧脚本已失效」** | 改完扩展后在 `chrome://extensions` 点过「重新加载」——老页面里的脚本已经死了，**按 F5 刷新该页面**即可 |
| **不确定页面里跑的是不是最新脚本** | 看面板标题右边的版本号（如 `v0.1.0`），或日志第一行 `页面脚本已加载 {版本:v0.1.0}`。没有版本号 = 页面里还是旧脚本 → 刷新扩展后在京东页面按 F5 |
| 测试取现成评价显示 `������÷` 这类乱码 | 那不是字符实体，是**编码**问题：京东老接口（`club.jd.com/comment/...`、`discussion/...`）返回 **GBK** 字节，按 UTF-8 硬解就是这个样子。现已自动识别并按 GBK 解码，日志会写「响应不是 UTF-8，已按 GBK 解码」 |
| 文案里出现 `&ldquo;` / `&rdquo;` | 这是字符实体，已自动还原成 `“ ”`（分号丢了也认）；日志若出现「检测到未还原的字符实体」说明还有漏网，把日志发我 |
| 出问题想定位 | 点面板「下载」把日志存下来 —— 里面有每一步的文案字数、图片张数、页面认账情况、点击与反馈片段 |
| 老评价页配图注入失败 | 京东偶尔改上传组件；先用「模拟」跑一单看面板提示，再据此改 `src/content.js` 里的 `findFileInputForSku` |
| 新发布页找不到正文框 | 改 `newPublishStep()` 里的 `textarea.rate-comment-content-textarea` |

## 与旧方案的关系
